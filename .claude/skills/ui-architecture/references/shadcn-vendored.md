# Scenario 7 — shadcn/ui (vendored components)

## Detection signals
- `components.json` at the project root (shadcn's official CLI config: defines `aliases`,
  `style`, the `tailwind.config` path, etc.).
- `src/components/ui/*.tsx` (or `components/ui/*` depending on configured aliases) with
  Radix UI-based primitives (`@radix-ui/react-*` in `package.json`).
- A `cn()` utility function (class merging with `clsx`/`tailwind-merge`), typically in
  `lib/utils.ts`.
- Tailwind with CSS theme variables (`--background`, `--foreground`, etc.) in `globals.css`.
- **Key concept**: these are NOT an npm dependency — they're copied/generated code inside the
  repo (`npx shadcn add button`) and edited directly as your own code.

## Typical structure
```
components.json
src/
  components/
    ui/               primitives generated by shadcn — Button, Dialog, Input, DropdownMenu...
    <rest>/           app-specific components, composed from components/ui
  lib/
    utils.ts          cn() and other shared helpers
app/ (or pages/)
```

## Where a new component goes
- **A new primitive not in shadcn's catalog** (or a generic variant of an existing one) →
  `components/ui/`, following the same pattern as the other files there (forwardRef, `cva()`
  for variants, `cn()` for class merging).
- **Before hand-writing one**, check whether it already exists in shadcn's official catalog
  and suggest `npx shadcn add <component>` instead of writing it from scratch — it's faster
  and keeps consistency with the rest of `components/ui/`.
- **A business composition** (uses one or more `components/ui/` pieces but knows app data/
  routes) → does NOT go in `components/ui/`, it goes directly in `components/` or in the
  feature/page folder that uses it.

## Notes / tradeoffs
- Since this is vendored code (not a package), **updating a shadcn component = editing it
  directly** — there's no "upstream" to pull automatically except re-running the `add` command
  (which overwrites local changes if you're not careful). If the component has already been
  customized, warn before overwriting it with the CLI.
- Don't move anything out of `components/ui/` into a supposed separate "design system" unless
  the user explicitly asks — it's the expected convention for this pattern and moving it
  breaks the `npx shadcn add` update flow going forward.
